# 项目任务：开发 GScratchpad 即时记事本

## 1. 项目目标

请为 Ubuntu 26.04 LTS 从零开发一款名为 **GScratchpad** 的原生桌面即时记事本。

这是一款用于临时记录、快速输入和保存碎片化信息的轻量级应用。

它不是传统文件编辑器，也不是复杂的知识管理软件。

核心体验：

- 打开应用即可输入内容。
- 不需要手动保存。
- 关闭标签页时不询问是否保存。
- 退出应用时不询问是否保存。
- 重新启动应用后，自动恢复之前的全部标签页和内容。
- 所有数据保存在本地，不依赖云服务。

请直接完成实际开发，不要只输出产品方案、UI 图片或静态 HTML 原型。

## 2. 运行环境与技术约束

目标环境：Ubuntu 26.04 LTS。

优先使用 GNOME 原生技术：

- GTK4
- libadwaita
- GtkSourceView 5
- SQLite
- GObject Introspection / PyGObject，或经过充分论证的原生 GTK 绑定。

优先采用 Python + PyGObject，以降低开发和维护复杂度。

具体依赖必须先检查 Ubuntu 26.04 官方 APT 软件包是否存在，再决定实现方式。

禁止：
- 将 Electron 或浏览器网页包装成桌面应用。
- 使用远程 Web 服务实现核心功能。
- 依赖在线 CDN 加载 Markdown、Mermaid 或数学公式组件。
- 引入没有必要的庞大运行时。
- 使用其他操作系统的安装命令和配置方式。

## 3. 用户界面设计

采用 GTK4 + libadwaita，遵循 GNOME Human Interface Guidelines。

视觉要求：

- 现代、精致、克制。
- 原生 GNOME 桌面风格。
- 支持系统浅色和深色主题。
- 合理使用圆角、留白和细腻的过渡动画。
- 不要使用过多渐变、阴影和装饰。
- 界面简洁，编辑区域占据主要空间。

主界面布局：

### 顶部区域
- 应用名称和窗口控制。
- 多标签页栏。
- 新建标签按钮。
- 标签关闭按钮。
- 编辑模式切换按钮。
- 更多操作菜单。

### 编辑区域
- 纯净的文本输入区域。
- 支持 TXT 和 Markdown。
- Markdown 提供语法高亮。
- 支持源码编辑和即时预览两种模式。
- 支持分屏预览。
- 支持键盘快捷键。

### 底部状态栏
- 当前文本字符数。
- 当前字数。
- 文档格式。
- 自动保存状态。

## 4. 多标签页与文档管理

必须支持：

1. 新建多个标签页。
2. 标签页切换。
3. 标签页重命名。
4. 标签页关闭。
5. 标签页顺序调整。
6. 记住上次活动标签。
7. 重启后恢复全部标签页及其顺序。

每个标签页都是独立的文档。

支持两种格式：

- TXT：纯文本。
- MD：Markdown。

新建标签页默认使用 TXT。

允许在标签页中切换文档格式。

重要：关闭标签页不等于删除文档。

关闭标签页只关闭当前视图，文档仍然保留在本地。只有用户通过明确的删除操作，才能删除文档。

## 5. 自动持久化机制

这是整个项目最重要的功能，必须优先保证可靠性。

要求：

- 用户输入后自动保存。
- 输入停止约 300ms 后触发防抖保存。
- 保存过程不阻塞 UI。
- 关闭标签页前确保内容已经持久化。
- 应用退出时确保所有内容已经写入。
- 崩溃或意外断电后，尽可能恢复最近一次成功写入的内容。
- 重启后恢复所有标签页及其内容。
- 不出现任何未保存提示。
- 不要求用户执行 Ctrl+S。

使用 SQLite 管理文档元数据、标签顺序、格式、活动标签等信息。

文档内容可以存储在独立 TXT / MD 文件中。

采用事务、原子写入和必要的恢复日志机制，避免写入中断导致数据损坏。

自动保存失败时，必须在界面中明确显示错误，不能虚假显示保存成功。

## 6. Markdown 功能

Markdown 编辑器至少支持：

- 标题。
- 粗体、斜体。
- 引用。
- 有序和无序列表。
- 代码块和语法高亮。
- 表格。
- 链接。
- 图片。
- 数学公式。
- Mermaid 流程图。

数学公式支持 LaTeX 常用语法。

Mermaid 必须能够在本地离线渲染。

源码模式、即时预览模式和分屏模式之间可以自由切换。

## 7. 图片管理

支持：

- 拖放图片到编辑区域。
- 从文件选择器插入图片。
- 自动复制图片到应用资源目录。
- 自动生成 Markdown 图片引用。
- 图片与对应文档关联。
- 不因原始图片被移动或删除而丢失已导入图片。

建议目录结构：

~/.local/share/gnome-scratchpad/

├── scratchpad.db
├── notes/
│   ├── note-001.txt
│   └── note-002.md
├── assets/
│   └── note-002/
└── recovery/

## 8. PDF 导出

支持将 Markdown 文档导出为 PDF。

要求：

- 保留标题层级。
- 保留代码块和表格。
- 保留数学公式。
- 尽可能保留 Mermaid 图表。
- 图片正常显示。
- 支持中文字体。
- 支持 A4 页面排版。

导出功能不应影响自动保存机制。

## 9. 快捷键

至少支持：

- Ctrl+N：新建标签。
- Ctrl+W：关闭当前标签，但保留文档。
- Ctrl+Tab：切换下一个标签。
- Ctrl+Shift+Tab：切换上一个标签。
- Ctrl+1 至 Ctrl+9：切换指定标签。
- Ctrl+F：查找。
- Ctrl+H：替换。
- Ctrl+S：可以保留为立即保存操作，但不应成为必要步骤。
- Ctrl+Shift+P：切换源码与预览模式。

## 10. 交付要求

请按以下阶段实施：

第一阶段：检查 Ubuntu 26.04 的依赖、技术可行性和组件兼容性。

第二阶段：建立项目结构，实现 GTK4 / libadwaita 主窗口和多标签 UI。

第三阶段：实现 TXT / Markdown 编辑、即时预览和格式切换。

第四阶段：实现 SQLite 元数据管理、自动保存、异常恢复和启动恢复。

第五阶段：实现图片管理、数学公式、Mermaid 和 PDF 导出。

第六阶段：进行功能测试、异常退出测试、重启恢复测试和数据完整性测试。

第七阶段：生成 Ubuntu 26.04 可用的安装包，优先考虑 DEB。

最终交付：

- 完整项目源代码。
- README.md。
- requirements 或依赖说明。
- 安装脚本。
- 卸载脚本。
- 可安装的 DEB 包。
- 桌面启动器。
- 应用图标。
- 功能测试报告。

## 11. 验收标准

必须逐项验证：

1. 启动应用后能够直接输入文字。
2. 输入内容后无需手动保存。
3. 关闭标签页不弹出保存提示。
4. 退出应用不弹出保存提示。
5. 重新启动后恢复全部标签页。
6. TXT 内容和 Markdown 内容均能正确恢复。
7. 多标签页内容互不覆盖。
8. Markdown 公式和 Mermaid 能够正常渲染。
9. 图片导入后能够正常显示。
10. PDF 导出结果正常。
11. 强制终止应用后，能够恢复最近一次成功持久化的内容。
12. 全部功能不依赖网络服务。

请先检查环境和依赖，然后直接开始开发。

如果某项功能无法可靠实现，请明确说明技术限制，提供可行的本地替代实现，不要用虚假的按钮或静态界面冒充功能。

不要只停留在计划阶段，最终必须交付可运行的软件。
